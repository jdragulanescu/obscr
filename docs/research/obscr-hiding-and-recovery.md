# Obscr hiding and damage recovery: research findings

**Research date:** 2026-10-13. **Status:** investigation, not a product decision or recovery guarantee. Scope: [Find supported hiding and damage-repair methods](https://github.com/jdragulanescu/obscr/issues/15), within [Harden Obscr security and preserve repeatable attack checks](https://github.com/jdragulanescu/obscr/issues/11).

## TL;DR

- **Treat concealment and recovery as separate objectives.** S-UNIWARD assigns content-sensitive modification costs; syndrome-trellis coding (STC) embeds a message while minimizing those costs. Neither supplies channel error correction or geometric synchronization. They are credible candidates for less detectable embedding in an unchanged pixel grid, not evidence of survival through resizing or JPEG sharing. [UNIWARD §§3–6][uniward] [STC §§III–V][stc-paper]
- **Limited pixel damage has a practical investigation path:** a protected binary envelope, authenticated encryption, outer Reed–Solomon (RS) or BCH error correction, and interleaving. It costs payload capacity and additional embedding changes. An erasure-only library is not a substitute for correcting unknown corrupted bytes. No Obscr recovery rate has been measured. [RFC 5510 §§3,8,9][rs-rfc] [RS decoder][zxing-decoder]
- **Resize/JPEG recovery requires a different carrier and synchronization design, not just more copies of RGB lowest bits.** Transform-domain quantization-index modulation (QIM) is a classical candidate; learned watermarking provides useful comparison evidence. TrustMark is particularly instructive, but its public detection objective, tiny payload, and decode-only upstream JavaScript example make it unsuitable as a drop-in confidential-message transport. [QIM][qim] [TrustMark paper §§1,3,4][trustmark-paper] [JS implementation][trustmark-js]
- **Licenses materially constrain reuse.** The inspected S-UNIWARD source permits educational/research/non-profit use, not general MIT-style redistribution. The STC toolbox has a public-use statement but no clear blanket redistribution license in the inspected archive; it also includes differently licensed helper files. Do not copy either into Obscr on the assumption that academic availability means permissive licensing. [DDE downloads][dde] [S-UNIWARD archive][suni-archive] [STC distribution][stc-site]
- **Available building blocks are not an assembled solution.** `@zxing/library` 0.23.0 has an Apache-2.0 TypeScript RS error decoder; AFF3CT 4.7.1 offers MIT C++ FEC components; TrustMark's inspected source declares Python version 0.9.2 and MIT code/model licensing. Browser/Node integration, dependency obligations, framing, concealment, and real sharing-path recovery remain unvalidated.

## 1. Evidence boundary and local integration constraints

This report reads papers, standards, upstream source and license files, and Obscr's existing transport. **No application changes, installs, builds, tests, prototypes, benchmarks, or sharing-path trials were performed.** Library code was inspected, not executed. Archive contents were read in memory; no reference implementation was installed. Version identifiers below are observed releases, manifests or source snapshots, not predictions or claims of latest support. **[INFERENCE]** marks deductions that are not measured Obscr results; trial configurations are proposals.

The current shared [`lib/steg-core.js`](../../lib/steg-core.js) extracts/writes one least-significant bit of each RGB channel, skipping alpha. Nominal capacity is `3 × width × height` bits for its RGBA buffer. `prepare_write_data` permutes positions across the entire capacity; `write_lsb` defaults to filling every unused position with `Math.random()` bits. This is nominal storage capacity, not a statistically safe payload budget.

Both [`lib/steg.js`](../../lib/steg.js) and the browser's [`app/src/lib/steg.js`](../../app/src/lib/steg.js) decode and encode through `pngjs` and call `str_to_bits(..., 1)` / `bits_to_str(..., 1)`: the copy/majority-vote helpers in [`lib/utils.js`](../../lib/utils.js) provide **no active redundancy** on these paths. The writer appends 24 one-bits; the reader stops at the first byte `255`. This is a terminator, not a protected length or authenticated frame boundary.

[`lib/crypto.js`](../../lib/crypto.js) encodes an AES-256-GCM envelope as Base64 `salt:nonce:ciphertext:tag[:1]`, with a 32-byte salt, 12-byte nonce and 16-byte tag; optional gzip precedes encryption. A binary FEC path would have to preserve the whole cryptographic envelope and coordinate framing with both adapters. It must not try to repair a UTF-8 string after corrupted bytes have already been interpreted as text. [`package.json`](../../package.json) declares MIT licensing, ESM, `pngjs ^6.0.0`, and distribution of `bin/` and `lib/` only: new WASM/model assets would need an explicit packaging and offline-PWA strategy. These are integration constraints, not changes made here.

## 2. Hiding candidates and what their evidence actually supports

| Candidate | Evidence and useful property | Cost and boundary for Obscr |
|---|---|---|
| Existing RGB LSB, filler on/off | A necessary control using the actual implementation; filler-off preserves unselected channels. | Not content-adaptive; placement secrecy is not statistical cover preservation. Neither variant repairs damage. |
| **S-UNIWARD + actual STC message coding** | Directional wavelet residuals discourage changes in smooth or predictable regions; ternary ±1 operations and STC minimize additive distortion for a target message. The decoder need not know the original cover or the encoder's cost map. [UNIWARD §3][uniward] [STC §IV][stc-paper] | Filtering, cost buffers and trellis computation; STC time/space grows as `O(n × 2^h)` with constraint height `h`. Color-channel policy needs evaluation: the UNIWARD paper's main source is grayscale BOSSbase, not Obscr's RGB photographs. License clearance or independent implementation required. |
| **WOW as a spatial comparator** | Another directional-filter cost design; the UNIWARD paper finds similar spatial security under its tested rich-model detectors. [UNIWARD §§3.5,6.1][uniward] | Not an independent robustness layer; no reason from that comparison to prefer it without matched RGB trials. DDE research-use terms apply to the distribution; its individual archive was not inspected for adoption. |
| **J-UNIWARD / JPEG coefficient embedding** | Applies distortion minimization to quantized DCT coefficients. A JPEG-domain control can avoid first converting an existing JPEG into an RGB-LSB carrier. [UNIWARD §§2,3,6.2][uniward] | A JPEG file can carry data without surviving *another* JPEG encoding. Requantization, coefficient eligibility changes and grid shifts can break extraction. Requires coefficient-level codec access absent from the current PNG path, plus separate licensing and dependencies review. |
| **QIM / spread-transform dither modulation, with outer FEC** | Chen–Wornell explicitly analyze rate–distortion–robustness tradeoffs and coded quantizer-based embedding, including transform representations. [QIM §§II,V][qim] | A candidate for controlled compression/noise trials, not a ready Obscr package. Quantizer spacing, transform bands, clipping, color conversion, synchronization and extraction confidence must be specified. The paper's bounded/additive channel results do not prove arbitrary crop/resize robustness or low detectability. |
| **TrustMark learned watermarking** | Official implementation, public models, resolution scaling, noise training including crop/resize/JPEG, and optional BCH coding. [Paper §§3–4][trustmark-paper] | Explicitly a **non-steganographic**, publicly detectable provenance watermark. Upstream JS example only decodes. Raw carrier is 100 bits; protected data is only 40–75 bits depending on schema. Cannot hold even Obscr's present 16-byte authentication tag, let alone its envelope. A pointer to externally stored ciphertext would change offline/self-contained semantics, privacy and availability; it is a human product choice, not a workaround adopted here. |

**STC is embedding coding, not repair coding.** Its extraction is a syndrome `m = H·P(y)`. After carrier-bit error vector `e`, the extracted message becomes `m' = m + H·e` in binary arithmetic. **[INFERENCE]** A changed carrier bit can therefore damage multiple extracted message bits; an outer channel code must be sized against *post-STC message errors*, not just damaged pixels. Receiver synchronization still requires the same carrier ordering, matrix and frame length. [STC equation (13), §§IV–V][stc-paper]

**A simulator is not a message codec.** The inspected `S-UNIWARD_matlab/matlab/S_UNIWARD.m` accepts an image and payload rate, then samples changes via `EmbeddingSimulator`; it does not accept or recover the user's message. Its distribution is useful for research comparison, but cannot establish end-to-end recovery. The UNIWARD paper itself distinguishes simulated payload–distortion bounds from an actual STC implementation. [Source archive][suni-archive] [UNIWARD §6][uniward]

## 4. Distinguish the failure channels

| Event | What fails; what recovery would require |
|---|---|
| Small changes to decoded RGB values, same dimensions and coordinates | Direct LSB transport gets bit substitutions; outer error correction can help within its actual codeword budget. ±1 changes usually toggle parity, while ±2 does not; random byte replacement and an “N pixels changed” count describe different channels. STC adds syndrome error propagation. |
| Dimensions change | Current permutation depends on the number of carrier positions. A different sample count changes the permutation and mapping, not merely some bits. Even equal-area reshaping is not equivalent pixel geometry. Original dimensions in a header do not reconstruct removed samples. |
| Resizing | Interpolation mixes/replaces samples and changes the coordinate grid. Restoring the old dimensions does not restore old LSBs. Robust carriers need a specified normalized representation, alignment/synchronization and residual-error model. |
| Cropping, translation or rotation | Missing samples plus unknown origin/orientation. Once registered, known missing positions *may* become erasures; without registration, the error-code decoder receives the wrong sequence. Pilots, repeated tiles, feature alignment or bounded geometric search all cost capacity, time or detectable structure; none is specified by STC or RS alone. |
| Ordinary lossy JPEG encoding/recompression | Block DCT, quantization, reconstruction and implementation-dependent sample conversions can alter many values/coefficient parities. “JPEG quality 85” alone is not a standardized channel description: record codec, quantization tables, subsampling and sequence. A JPEG-domain hiding algorithm is not inherently recompression-resistant. [T.81 §§4,A,F][jpeg] [UNIWARD §2.2][uniward] |
| Pixel decoding/re-encoding | PNG is lossless for its encoded samples, but a pipeline may change bit depth, palette expansion, color profile/gamma, alpha compositing or orientation. PNG uses unassociated alpha; compositing is not sample-preserving. Compare actual decoded buffers, not screenshots or filename extensions. Existing browser extraction uses `pngjs`, not a Canvas screenshot path. [PNG §§4,6–8,13][png] |
| PNG-container corruption | A damaged chunk CRC, critical header, filter byte or compressed IDAT stream can prevent pixel decoding altogether. PNG CRCs **detect** corruption; they do not supply message repair. The present adapters must decode PNG before extracting hidden bits, so payload FEC cannot be assumed to repair the enclosing file. Container recovery needs an external intact copy/transport repair or a separately evaluated tolerant decoder; report it independently. [PNG §§4.10,5.3,13.1][png] |

Neither carrier redundancy nor authentication prevents an active sender/platform/adversary from destroying the whole image. A claim such as “survives sharing” must name the service, delivery option, input/output dimensions, transformations and observed dates.

## 5. Channel repair, envelope ordering and detection signatures

### Code families

| Family | Appropriate experiment | Overhead, failure and limits |
|---|---|---|
| Odd repetition + majority | Simple baseline, including 3 and 5 copies of each bit. | Rates 1/3 and 1/5; a bit fails if a majority of its copies are wrong. Nearby copies can fail together. Expensive compared with block coding and does not solve synchronization. Existing helpers alone do not protect all framing. |
| Binary BCH | Short bit-oriented frames or especially protected bootstrap fields; deterministic algebraic decoding. TrustMark supplies a concrete BCH application. [Schema docs][trustmark-config] | Choose actual `(n,k,t)` parameters and shortening rules, not just “BCH.” More parity reduces user data; beyond the correction radius a decoder may fail or miscorrect. Full-message authenticity remains necessary. |
| RS over GF(256), **unknown-error decoder** | Byte-oriented encrypted envelopes with scattered or interleaved burst errors. [Decoder][zxing-decoder] [RS parameters][aff3ct-rs-encoder] | `n-k` parity symbols, correcting at most `floor((n-k)/2)` unknown symbol errors per codeword. A mixed error/erasure decoder has bound `2e+s <= n-k`; that does not imply every RS API supports erasures. One bad bit can spoil an entire byte symbol. |
| RS erasure coding | Missing/discarded shards with trustworthy identification, e.g. registered missing tiles or separately checked chunks. [RFC 5510][rs-rfc] | Any `k` intact symbols from `n` suffice in the specified MDS construction. Unknown corrupt shards violate the premise. A whole-message GCM failure cannot identify which shard is bad; per-shard integrity adds overhead. CRC can classify accidental damage but is not adversarial authentication. [RFC 5510 §9.2.2][rs-rfc] |
| LDPC / convolutional channel codes | Longer messages and a robust extractor that exposes calibrated soft information. AFF3CT documents hard/soft iterative LDPC options. [LDPC docs][aff3ct-ldpc] | Matrix/trellis choice, likelihood calibration, block length and iteration limits become part of the protocol and performance envelope. An iterative decoder may not converge or may reach the wrong codeword; a zero syndrome is not authentication. More complex than the initial small-message RS/BCH experiment. |

**Proposed RS trial parameters, not recovery promises:** `(255,239)`, `(255,223)`, `(255,191)` over byte symbols, with respectively 16, 32 and 64 parity bytes, correcting at most 8, 16 and 32 unknown erroneous bytes *per aligned codeword*. Parity cost relative to useful block bytes is respectively `16/239`, `32/223`, `64/191`; these are arithmetic code properties, not damaged-image percentages. Final-block shortening/padding and all header bytes must be counted. [RS encoder parameters][aff3ct-rs-encoder] [Decoder behavior][aff3ct-rs]

**Interleaving:** spread neighboring extracted symbols across codewords so a localized burst need not exhaust one block. It adds no parity itself, but needs stable coordinates, a reversible permutation and bounded storage. The current full-image placement permutation may already disperse some physical damage for direct LSB; additional interleaving is not automatically beneficial. **[INFERENCE]** Bit-level scattering can spread a few flips into many RS bytes, while keeping byte bits together can concentrate them; compare bit-, byte- and tile-level mappings using measured post-extraction error distributions. For STC, interleave outer-code symbols before embedding and evaluate errors after syndrome extraction.

### Proposed processing order, not a settled wire format

1. Optionally compress plaintext, then form a versioned, bounded binary envelope and **AEAD-encrypt** it. Authenticate interpretation-critical metadata (version, length, compression flag, code profile, geometry/profile identifiers) as associated data or inside the plaintext.
2. **FEC-encode ciphertext plus its authentication tag and the metadata needed to reconstruct decryption inputs**, then interleave/map and embed. Protect salt/nonce and bootstrap as well as message bytes. Encoding redundancy only inside authenticated encryption would leave no usable repair layer before a damaged ciphertext fails authentication.
3. On receipt: decode pixels and establish geometry; recover a separately protected, fixed/bounded bootstrap; validate limits; select the agreed FEC/interleaving profile; extract and repair; reconstruct the envelope; **authenticate before returning any plaintext**, then decompress within bounds. FEC success, readable text, a checksum, a zero syndrome or a watermark-presence flag is not authenticated recovery. [RFC 5116 §§2.1–2.3][aead] [RFC 5510 §9][rs-rfc]

The bootstrap must not depend on the very length, code rate, salt or placement seed it is needed to recover. Candidate choices are a fixed protected bootstrap at a predefined mapping, or a small pre-agreed set of bounded decoder profiles. Replicated headers are useful only if copies are spatially separated and have an unambiguous validation/selection rule; conflicting copies must not silently override authenticated parameters. A damaged header cannot authorize arbitrary allocations, decompression, geometry searches or decoder iterations. Placement randomization requiring a per-image salt has the same bootstrap problem.

**Public redundancy can expose the message's presence. [INFERENCE]** For a public linear code and discoverable framing, even uniformly random encrypted data occupies only the code's codeword subset: a public parity-check/syndrome test can distinguish it from unrestricted random bits. Fixed magic, repeated headers, systematic parity and pilot grids can also be signatures. Secret placement complicates extraction of those tests but does not prove they are impossible. Keyed post-FEC whitening is a candidate to study, not a concealment theorem: it needs independently derived key material and non-reused per-image context, and its bootstrap must remain recoverable. Do not wrap FEC in an outer AEAD layer whose authentication must succeed before repair. The detectability evaluation must include the real header, parity, synchronization and padding, not only encrypted payload bits. [STC's linear-code formulation][stc-paper] [AEAD semantics][aead]

## 6. Original-cover and multiple-image adversaries

- **Exact original available:** pixel/coefficient differencing exposes modifications despite password-based order or ciphertext confidentiality. A nonempty difference alone does not prove steganography—editing and re-encoding also cause differences—but an attacker can inspect the characteristic modification pattern. **[INFERENCE]** Neither S-UNIWARD nor secret placement provides the same threat model once the exact cover is known; storing or publishing cover/stego pairs defeats reliance on cover uncertainty.
- **Multiple encodings of the same cover:** repeated comparison reveals changed positions and cross-image patterns. Obscr's order is deterministic for the same password and capacity. Fresh encryption randomness does not make that placement independent. **[INFERENCE]** Different ciphertexts and independent full-image filler can produce broad pairwise LSB differences; no quantitative detection advantage is claimed. Collusion/averaging can also target robust watermarks; measure repeated-cover cases separately from single-image detection.
- **Multiple unrelated images from one sender:** evidence can be aggregated, and acquisition/development artifacts can become confounders. A train/test split that includes related images on both sides can exaggerate apparent detector quality. The UNIWARD study controls the cover source and compressor precisely; its rates cannot be transferred to an uncontrolled photo collection. [UNIWARD §§2.2,4][uniward]
- **Randomized placement and filler:** placement changes where bits are read, not the fact that parity statistics are changed. **[INFERENCE]** Under independent unbiased replacement, each written channel has a one-half probability of differing from its previous LSB, so writing filler everywhere has expected change count about half of all RGB channel positions even for a short message. This is an idealized expectation, not a run or a detection rate. Filler-off reduces that unnecessary modification but still needs empirical steganalysis; filler-on does not become safe merely because it conceals the used prefix.

An earlier solid-color demonstration says nothing quantitative about ordinary-photo detection. Flat images belong in stress tests, not as a substitute for a representative photo corpus or a population-wide detection estimate.

## 7. Proposed experiment matrix

**Everything in this section is future work.** Candidate ranges explore tradeoffs; none is a minimum success promise. Preserve exact inputs, encoded and transformed files, seeds, code/model hashes, codec parameters and machine/runtime versions so checks can be repeated after changes.

### Corpus and candidate setup

- Use a separately licensed, consent-appropriate RGB photo corpus with texture/noise, smooth areas, low light and saturated colors; keep screenshots, illustrations, flat colors and alpha-heavy images as labeled strata. Include PNG palette/8-/16-bit decoding cases separately. Proposed engineering pilot: 100 covers per stratum and 10 independently seeded payload/placement/damage repetitions per feasible condition; do not treat those correlated repetitions as independent images in confidence intervals.
- Fix cover geometry bins at 512×512, 1024×768 and 2048×1536 for controlled tests; retain native-resolution images for external validity. Group all derivatives of an original/camera session into the same data split.
- Payloads: random binary contents and UTF-8 messages at 32, 256, 1024 and 4096 useful bytes, plus matched total embedded rates of 0.01, 0.05, 0.1 and 0.2 bits per pixel where feasible. Record both useful and total coded bits; report capacity rejection rather than shrinking a message. JPEG candidates also report bits per nonzero AC coefficient. Compression on/off is explicit. TrustMark is a **separate 40/61/68/75-bit watermark comparator**, not a competing full-message result.
- Compare existing filler-on/off controls; direct LSB + outer RS/BCH; S-UNIWARD + real STC with/without identical outer codes; and a specified QIM/robust-carrier candidate. Suggested STC heights: 6, 8, 10, 12, with declared block sizes and wet-pixel rules. Compare no interleaving with byte/bit/tile layouts, interleave depths 4 and 16, and stronger fixed bootstrap profiles. Hold useful payload fixed for one comparison and total carrier occupancy fixed for another; otherwise redundancy can unfairly change the comparison.

### Required recorded outcomes and detection evaluation

For every condition record **exact authenticated recovery** (tag accepted and original plaintext bytes exactly equal), capacity rejection, bootstrap/synchronization failure, image parse failure, FEC failure, authentication failure and wrong authenticated output as separate outcomes. Record raw/post-extraction bit and byte errors, error distribution per codeword, corrected-symbol count, bootstrap loss and any soft-confidence calibration. Include wrong-password, unencoded-cover and over-limit-damage negatives; cap and record search attempts. Do not collapse successful bit recovery into successful messages.

Measure encoding/decoding latency by phase (image codec, KDF/AEAD, embedding, synchronization, FEC), cold/WASM/model startup and warm median/tail timings, peak memory, output bytes and browser main-thread blocking. Identify actual browser, Node version and device, including a constrained mobile device. A fast native paper result is not a browser latency result.

Report embedding-only RGB/luminance PSNR and SSIM with exact definitions/ranges, changed-sample fraction, residual maps and human visual inspection; compare transformed stego to an equivalently transformed unencoded cover separately. Do not attribute JPEG degradation to embedding. Visual imperceptibility is distinct from statistical nondetectability.

For detection, build matched cover/stego datasets **with real envelopes and ECC**, controlled image codecs and identical preprocessing. Begin with targeted LSB/parity tests and an SRM/ensemble spatial baseline (JPEG rich-model equivalent for coefficient methods), then a documented contemporary learned detector. Keep original/derivative groups separate across train/validation/test; include held-out acquisition sources and payloads to expose cover-source mismatch. Report ROC/AUC, true-positive rate at explicitly stated false-positive rates (candidate operating points 1% and 0.1% only where enough negatives support estimation), balanced error, uncertainty intervals grouped by cover, per-stratum results, and training/data costs. Sample size must be chosen for the desired precision at the low false-positive operating point; the engineering pilot alone does not establish it. Run separate original-cover and repeated-cover comparisons, including 2, 5 and 10 encodings per cover. [UNIWARD §4 supplies a reproducible historical baseline, not modern deployment assurance][uniward]

## 8. Transferable conclusions and unresolved decisions

**Transferable:** STC's embedding/repair distinction and computational form; RS/BCH code properties under their stated channels; AEAD's all-or-failure semantics; PNG container-versus-pixel distinction; QIM's conditional robustness tradeoff; TrustMark's public-watermark objective and bounded schema capacity. **Not transferable:** published steganalysis error, watermark bit accuracy, GPU latency or image-quality averages as Obscr results. UNIWARD used BOSSbase 1.01 grayscale images with specified rich models; TrustMark's reported experimental results explicitly did **not** use BCH, and bit accuracy is not exact authenticated message recovery. [UNIWARD §4][uniward] [TrustMark §§4.1,4.5][trustmark-paper]

When a recipient receives an altered image, these remain genuine product alternatives:

- **(a) Require original, unmodified PNG delivery; investigate less detectable embedding.** Preserves a simpler, higher-capacity carrier and focuses concealment evaluation; recipients must obtain the original file, and routine photo sharing may destroy it.
- **(b) Repair limited same-grid pixel damage.** Add a protected envelope, outer FEC and measured interleaving; costs capacity, latency and potentially detectability, without promising resize/JPEG recovery.
- **(c) Support named photo-sharing transformations with a robust carrier.** Requires synchronization and a different embedding/extraction path; likely lower useful capacity and a different detectability/visual-quality tradeoff **[INFERENCE]**. A tiny public watermark identifier would additionally require external storage and change the product's privacy/offline contract.

**Research sequencing recommendation:** compare (a) and (b) on the same covers and authenticated messages first, while evaluating (c) as a separately labeled carrier experiment, because that separates concealment, coding and synchronization failures. This does **not** select a user-facing promise or exclude the already-approved resize/JPEG comparisons.

Precise unresolved facts/choices:

1. Rights-holder permission for production redistribution of the DDE S-UNIWARD implementation and an explicit core STC license; individual J-UNIWARD/WOW source and dependency license review if selected. Paper publication is not implementation or patent clearance.
2. A maintained, validated portable adaptive embed/extract implementation, including RGB cost/channel policy, deterministic matrices, edge/wet handling, block sizes and browser memory requirements; no such integrated artifact was established here.
3. Actual post-extraction errors, burst lengths and synchronization success for each carrier/channel; these determine RS/BCH/LDPC parameters, not an assumed percentage of recoverable pixels.
4. Envelope/bootstrap format, bounded version/profile discovery, per-image placement context, authenticated metadata, parity whitening policy, and resulting detection signature. No protocol has been agreed.
5. Supported browser/Node versions, permissible WASM/model size, offline requirements and device latency/memory budgets; notably whether Node >=24 is acceptable if adopting the examined ZXing package.
6. Which concrete sharing services and settings, message sizes, loss events and adversaries matter; whether original-cover or repeated-cover availability is in scope; and whether a public short identifier plus external storage is acceptable at all.
7. Acceptable empirically demonstrated recovery, visual quality and detectability tradeoffs, with uncertainty and exclusions. These require human choice after measurements; no universal success threshold follows from this research.
